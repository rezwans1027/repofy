# Private repository ingestion threat model

Run 06, September 19, 2026. See [ADR 0006](adr/0006-safe-snapshot-ingestion.md) for exact versions and limits.

Assets are GitHub credentials, private source/path names, consent, tenant membership, committed snapshot identity and worker resources. Untrusted inputs include repository files/names, tar/PAX headers, ignore files, provider response/redirect bodies, stale grants and delayed workers. Authenticated browser input still cannot choose an archive URL, branch, provider identity, owner or security policy. GitHub's TLS service is trusted to provide the requested commit; an archive is not independently proven to match a Git tree here.

| Threat | Implemented boundary | Verification / residual boundary |
|---|---|---|
| Cross-user guessed job/repository | Explicit actor, original job grants, confirmed private/org consent, active grant revision, no direct table ACLs | Real PostgreSQL owner/role tests; route actor still comes from verified auth |
| Moving branch / concurrent retry | Commit and encrypted branch persisted before download; first pin wins; no retry re-resolution | Independent PostgreSQL connection race and branch-change fixture |
| SSRF / credential redirect | Constructed exact-SHA API URL, manual bounded codeload-only redirect, no forwarded authorization/cookies | Adversarial destinations/refs tested; upstream layout changes fail closed |
| Path traversal / link/device / parser differential | Parse without filesystem unpacking, physical framing and strict parser, path/type/metadata guards | Traversal, Unicode collisions, links, expansion, truncation, PAX overrides and trailing members |
| CPU / disk / memory exhaustion | Stream limits, bounded metadata/file/context counts, elapsed timeout, short leases and absolute lifetime | Process driver heap cap/watchdog; production RSS/disk/concurrency supervision belongs to Run 07 |
| Ignore/encoding/scanner bypass | Whole-file exclusions precede context; all eligible UTF-8 and locators scanned; no repository scanner config or overrides | Order/negation, invalid encoding, unusual extensions, scanner exception and secret sentinels |
| Unrecognized secret or private data | Conservative packaged scanner and explicit limited coverage; no model adapter is enabled | Release corpus calibration and minimum model context required in Runs 12/16 |
| Prompt injection / repository execution | No installs, builds, hooks, config evaluation, child processes or network capability in the context | Child-process entry points instrumented in ingestion tests; Run 12 must treat source as untrusted data |
| Revocation / deletion during download | Uncached stage/read checks, two-second polling, abort propagation; SQL job/grant/lease fence at ready | Idle-body revocation, cancellation/deletion, independent stale-worker tests; publication fence remains mandatory |
| Source in errors / telemetry | Fixed failure codes without causes, no raw parser/provider messages, codeload/API telemetry suppression | Captured sentinel logs/errors and model-input substitute (the safe context); actual model egress remains future work |
| Crash / stale workspace / DB outage | Immediate raw deletion, no-follow private workspace, independent janitor, 30-minute absolute TTL | Abrupt process exit plus fresh-process sweep; Run 07 must schedule <=5-minute sweeps on every volume |
| Cross-policy cache reuse | Full manifest pinned and hashed; digest in canonical snapshot uniqueness and run/report validation | Different-limit policies produce separate artifacts; legacy identity remains separate |
| Locator/hash guessing | Encrypted relative locators and branch; repository-scoped keyed content/path fingerprints | Row/purpose substitution and export redaction tests; keys require managed deployment storage |

No filesystem or API capability is supplied to extractors through `SafeSnapshotContext`; trusted Node code outside that interface still has the host process's privileges. A compromised worker, GitHub service, database owner or managed key provider is outside this module's isolation guarantee. Production rollout also requires worker volume/backup policy, no source-bearing crash dumps, active cleanup monitoring and real installation tests. These remain named deployment gates, not a claim that local tests establish them.

## Run 16 disposition

The preceding table records the original Run 06 boundaries. Runs 07–15 now compose the durable worker, parser/aggregation policies, closed-choice model gateway, deterministic renderer and private report/feedback/comparison surfaces. The production model adapter exists but local deployment flags remain disabled. The [release evidence matrix](benchmarks/run16-release-evidence.md#failure-privacy-and-regression-disposition) and [actual verification](benchmarks/run16-verification.json) supersede “future run” verification notes above without changing those trust boundaries.

The 24-case frozen corpus exercises invalid credential-shaped text, mandatory/ignored paths, repository instructions, generated/vendor files, declared fork/template context and unknown history. Only application-authored statements and minimal structured facts reach model/generalized projections; zero sentinel disclosures and zero provenance score modifiers were observed. This does not establish complete secret detection. Exact source spans and claim membership are necessary checks, separate from human semantic review.

Real PostgreSQL checks cover owner/foreign nested membership, concurrency, SIGKILL of a claimant, lease/revocation/deletion fences, uncertain model outcomes, settlement connection loss, immutable reports, export and shared-reference deletion. Browser checks cover private/no-store responses, source-free metadata, account/cache switching, public-to-private location changes, copied owner URLs, feedback and provider-independent saved reads. Test-only workload/outage endpoints bind loopback and are never registered by the production app. Hosted credential traces are disabled; CI uploads only the synthetic readiness captures from that harness, plus separate failure screenshots for the explicitly requested dedicated-account legacy suite. No auth storage-state file is uploaded.

Residual release blockers are explicit in [run16-external-gates.json](benchmarks/run16-external-gates.json): live GitHub/model authorization, managed secrets/rotation, actual provider retention, native process/volume supervision, crash-dump and backup policy, cleanup through a deployed database/host outage, and hosted identity/PostgREST checks. Local fixture processes and test-clock lease/TTL advancement do not establish real elapsed-time cleanup on a deployed host. There are no enabled public/employer Feature 1 report routes; future disclosure/consent designs require their own threat review. Rollout remains **HOLD**.
