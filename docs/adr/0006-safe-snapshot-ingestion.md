# ADR 0006: Commit-pinned, bounded static ingestion

Accepted for Run 06, September 19, 2026. Requirements: ANA-002, ANA-004 foundations, ING-001–008. This is an internal worker module and synthetic process driver. Durable scheduling, deployment and model processing remain Runs 07–12.

## Identity and access

`SnapshotIngestionService.resolveSnapshot({actor, jobId, repositoryId})` derives the grant/account/installation from the owner's existing job. Private and organization grants must carry Run 05 consent. Fresh GitHub user/installation/repository checks precede resolving the default branch. `feature_one_ingestion_pin` commits provider ID, encrypted branch, exact 40-character SHA, grant revision, resolution time and policy before downloading anything. The first committed pin wins concurrent resolutions. Retries read that pin, never today's branch head. Changing limits or security policy requires a new job, not mutation of a pin.

`GitHubSnapshotSource` refreshes live authorization before every retrieval. The archive client builds `/repos/{owner}/{repo}/tarball/{sha}` itself, using verified names and the persisted SHA. GitHub documents contents-read permission, redirects and short-lived private archive URLs in its [archive API](https://docs.github.com/en/rest/repos/contents#download-a-repository-archive-tar), and recommends commit IDs for repeatable file contents in [archive stability guidance](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives). Compressed archive bytes are not a stable identity.

Our conservative GitHub.com redirect policy accepts at most two redirects, only HTTPS `codeload.github.com`, the same verified owner/repository and `legacy.tar.gz/{full SHA}`, with only an optional temporary `token` query. It rejects credentials, ports, fragments, other hosts, changed repositories and branch refs. Authorization is sent only to the initial API origin; cookies are omitted. URLs and response bodies are never persisted or logged. Sentry drops provider breadcrumbs and transactions containing provider/codeload child spans, including temporary URL query tokens. Undocumented destination changes fail closed and require review; GitHub Enterprise and alternate archive formats are unsupported. `Accept-Encoding: identity` prevents an unmetered HTTP decompression layer. The client counts actual streamed bytes, validates declared length and cancels interrupted/oversized bodies.

Every stage and context read checks the active owner/job/grant/revision and ingestion lease. A two-second heartbeat aborts idle downloads when access changes, cancellation/deletion is observed, or the database fails. Already-started network traffic is canceled on that observation; no zero-latency webhook guarantee is claimed. API metadata calls retain Run 04's bounded request timeout; default-branch resolution also has the configured 120-second overall budget. Ingestion database calls have a five-second deadline, including disposal attempts. No new fetch starts after a failing authorization checkpoint. Publication must still use Run 07's durable job fence and Run 02's final grant check.

## Parser and limits

Use pinned `tar@7.5.22` as a parser, never its filesystem unpacker. Its [maintainer documentation](https://github.com/isaacs/node-tar) describes strict parsing and bounded metadata; this version is newer than the fix for the [PAX size interpretation advisory](https://github.com/isaacs/node-tar/security/advisories/GHSA-vmf3-w455-68vh). A separate framing guard counts all physical headers, including empty metadata, rejects trailing nonzero members and requires a complete tar terminator. Only regular files, directories and bounded PAX path/time/comment metadata are supported. Size/sparse overrides, GNU extensions, devices, links and unknown entry types reject the archive.

Gzip output is metered before parsing. A valid first tar header is required before parser input, preventing nested compression from bypassing the decompressed-byte ceiling. Paths require one archive root; reject absolute/drive/traversal/backslash/control/bidi paths, conflicting parents and duplicate NFC-normalized names. No archive path, permission, owner or link is applied to the filesystem. Unicode paths are normalized for safe internal locators. The first streaming pass validates the archive and obtains the root `.repofyignore`; the second filters and scans files. This makes ignore behavior independent of archive ordering. Both passes have the same limits and cancellation signal.

| Limit | Default and hard ceiling | Outcome |
|---|---:|---|
| Compressed archive | 100 MiB (104,857,600 bytes) | Reject |
| Decompressed archive, including padding/metadata | 512 MiB per pass | Reject |
| Physical archive entries | 50,000 | Reject |
| Eligible text files | 10,000 | Reject |
| Individual text file | 1 MiB | Exclude whole file, counted reduced scope |
| Total retained UTF-8 text | 32 MiB | Reject |
| Total considered lines | 250,000 | Reject |
| Path | 1,024 UTF-8 bytes; 32 components including archive root | Reject |
| PAX entry / root ignore file | 64 KiB | Reject |
| Root ignore rules | 128; 256 characters and 16 wildcards per rule | Reject |
| Preparation after resolution | 120 seconds | Abort and clean up |
| Workspace/context absolute lifetime | 30 minutes | Abort / eligible for unconditional local sweep |
| Lease / access heartbeat | 60 seconds / 2 seconds | Expiry cannot be renewed by a stale attempt |

The PRD's MB defaults are interpreted as MiB explicitly. Deployment code may lower limits through `securityPolicy(overrides)`; repository/browser inputs cannot alter them. Raising ceilings requires a reviewed version change. Preparation buffers at most one bounded file at a time, plus bounded eligible text and file metadata. The synthetic process runs with a 256 MiB V8 old-generation limit and a parent watchdog. A production worker also needs an OS RSS cap (initial recommendation 512 MiB), disk quota, bounded concurrency and supervisor deadline in Run 07; a V8 old-generation limit alone is not a total native-memory limit.

Mandatory exclusions cover credential directories/files, environment files (including examples), key stores, data dumps, database/log/tabular files, dependency trees, generated/build output, binary extensions and bytes, and non-UTF-8 content. Generated markers also exclude a file. Root `.repofyignore` uses pinned [`ignore@7.0.9`](https://github.com/kaelzhang/node-ignore), with a documented bounded subset: comments, negation, `*`, `**`, `?`, root anchors and directory rules. Escapes, character classes, braces, control characters, traversal and oversized rules are rejected. Negation never overrides mandatory exclusions. Nested ignore files are not interpreted and are themselves excluded. `.gitignore`, repository scanner configuration and suppression comments are not loaded.

## Scanner decision and limitations

Use the packaged, versioned `repofy-static-secrets-1.0.0` scanner, an offline deterministic TypeScript filter. It checks both candidate locators and every eligible file, regardless of extension. It covers common provider tokens, private-key headers, JWTs, authenticated connection strings, credential assignments, high-entropy alphanumeric blobs, email addresses, US SSN shapes and Luhn-valid payment-card shapes. It returns only a boolean. No match values, positions, snippets or rule messages leave the scanner.

We considered CLI scanners and dynamically configured lint engines. This first ingestion boundary keeps an auditable bounded rule set with no executable dependency, repository plugin/config loading, secret verification requests or suppression capability. [Gitleaks' generic credential rule](https://github.com/gitleaks/gitleaks/blob/master/cmd/generate/config/rules/generic.go) documents the keyword/entropy approach; our scanner is independently implemented and does not claim Gitleaks' rule coverage. Rule changes require a policy version change and new fixture results.

Any positive excludes the **entire file**, including examples and false positives. There is no user allowlist, inline override, partial redaction or fallback to unscanned content. Scanner exceptions, invalid return values and version mismatches abort ingestion. Failures expose fixed codes only. Safe counts say `secret_or_sensitive_data`, without listing excluded paths or match categories. Malformed ignore rules also fail closed.

This detects likely secrets; it cannot establish that arbitrary source contains no sensitive information. Obfuscation, custom credential formats and unrecognized personal/health data remain limitations. Before real model egress, Run 12 must minimize inputs, rescan any newly composed snippets/metadata, establish provider handling and validate scanner coverage against the release corpus. Run 16 must measure false negatives and false positives. No claim of complete DLP or production scanner calibration is made here.

## Context, persistence and reuse

`prepareSafeSnapshot` exposes only `SafeSnapshotContext`: immutable pin identity, frozen policy and counts, `files()` and `readText(locatorId)`. Files have normalized scanned locators, UUIDs, byte/line counts and repository-scoped HMAC content hashes. ECMAScript private fields hide the content map, lease callbacks and storage handles. No disk path, raw archive, credential, transport or arbitrary network/file lookup is supplied. This constrains trusted extractors; it is not an OS sandbox for hostile JavaScript. Repository instructions are data, never commands. No semantic analysis or capability absence is asserted by successful ingestion.

Encrypted locators and branch provenance use Run 02's independent AES-GCM keyring and purpose/row binding. Content lookup uses repository-scoped HMAC with the independent fingerprint key, never persisted ordinary hashes of guessable private content. Only eligible scanned file metadata is retained in `ingestion_files`; exclusions retain counts only. `feature_one_export_v4` adds owner-scoped ingestion metadata and strips ciphertext, locator fingerprints, content hashes and lease tokens. Analysis/account deletion cascades this storage; cleanup can still remove orphan workspaces without the deleted row.

The SHA-256 policy digest includes exact scanner, exclusion, ignore, parser, coverage versions and all effective limits. Each job pin retains the full manifest. Canonical `repository_snapshots` uniqueness now includes that digest. Snapshot bundles, run versions and final report snapshots must agree on `securityPolicyHash` / `ingestionPolicyHash`. Existing artifacts use the distinct `legacy` database identity; optional contract fields preserve their readability. New workers must always supply the digest. Run 08 must construct canonical observations from this context, retain the policy digest, and use Run 02's returned canonical ID on reuse; ingestion metadata is not a semantic evidence bundle.

## Cleanup and rollout

Workspaces use a dedicated worker-owned 0700 root outside public/static directories, unique UUID directories and 0600 manifests/archives. Manifests contain only job/workspace UUIDs and timing metadata. Raw archives are removed **before** context handoff, not retained through later analysis. Error/cancel paths delete disk before attempting database disposal. `withSafeSnapshot` also disposes memory and leases after consumer success/failure. Disposal is idempotent and can be retried; it requires neither active repository access nor intake flags. JS cannot retract text a consumer already copied, so consumers must keep processing inside the scope and obey cancellation.

`WorkspaceManager.sweep(store.claimExpired)` is the startup/periodic janitor contract. Its database callback atomically fences expired leases, returns true for already disposed/missing attempts, and cannot renew an expired worker. Independently, local absolute 30-minute expiry removes orphans even during database outages; incomplete manifests use directory age. UUID-only traversal and no-follow file opens prevent a workspace symlink from directing cleanup elsewhere. Run 07 must schedule this on every worker volume at startup and every five minutes or less, retain it while intake is disabled, alert on failures, and enforce process limits. With that scheduler operating, crashed raw workspaces are removed within 35 minutes of creation, inside the PRD's 60-minute terminal target. Host/volume outages and backup retention need deployment policy; this run does not pretend a scheduler is deployed.

The local process driver explicitly exits after writing an archive, then starts a fresh janitor with an advanced test clock and verifies an empty volume. Unit tests also cover source sentinels, idle-stream revocation, ENOSPC, malformed archives and scanner failures. Real PostgreSQL connections test first-pin concurrency and lease fencing. These are synthetic checks, not real installation verification.

Apply `20260919000200_safe_snapshot_ingestion.sql` after Run 05, then deploy compatible contracts/backend. No migration or flag was applied remotely. No API route starts ingestion; the analysis action remains disabled. Roll back code by stopping intake and keeping cleanup running; retain the additive schema and encrypted artifacts, and use a forward migration for corrections. Run 07 owns actual scheduling and cancellation/billing orchestration; live GitHub private archive validation remains pending development-app credentials.
