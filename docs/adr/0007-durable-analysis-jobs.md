# ADR 0007: durable analysis jobs and settlement

Accepted September 19, 2026 for Run 07. The production handler registry remains incomplete until Runs 08–12 land. No public intake or paid analysis is enabled by this change.

PostgreSQL is the queue and source of truth. A separate, supervised worker claims one job using `FOR UPDATE SKIP LOCKED`. All state changes lock the job before its execution row, grants, and settlement. A random claim token, a 60-second renewable lease, a 15-minute attempt deadline, three attempts, and a 24-hour logical deadline bound recovery. Heartbeats run every 15 seconds; recovery runs every 30 seconds, without depending on HTTP requests or intake flags. PostgreSQL documents [SKIP LOCKED for queue consumers](https://www.postgresql.org/docs/17/sql-select.html) and [row/advisory lock semantics](https://www.postgresql.org/docs/17/explicit-locking.html).

Every source operation and write requires the current lease and captured grant revisions in the same database transaction. Run 06 ingestion leases remain subordinate to the job lease. A worker owns only its randomly named ingestion workspace; it cannot remove its replacement's workspace. Cancellation and deletion invalidate the claim. Deletion retains an owner-scoped, source-free idempotency tombstone until account deletion, preventing a delayed POST replay from recreating the job. Owner status, cancellation and retained report reads remain available with intake disabled.

The request preserves repository display order while its identity sorts repository IDs and normalizes options. Server policy freezes workflow/security/extractor/detector/coverage/aggregation/taxonomy/rubric/synthesis versions. All repositories are pinned before extraction. Retries reuse those pins and durable, owner-authorized snapshot references. The failure policy is `fail_all_v1`: one inaccessible or invalid repository fails the entire job. There is no implicit partial result or cross-owner report cache.

The initial entitlement is an explicit deployment allowlist, with the existing repository limit and two unfinished jobs per owner. Billing uses a separate analysis settlement ledger. Production has only `internal_free_v1` (zero units); advisor balances and prices are unchanged. `test_units_v1` exercises a separate test wallet in disposable database tests and is never selected by production configuration. Reservation/debit and job creation commit together; report, completion, and settlement commit together; terminal failure/cancellation and refund commit together. A reconciler repairs terminal settlement decisions. Stable logical job IDs are settlement keys. Paid/refunded jobs cannot resume or be charged again; a new logical request would require a new explicit pricing policy. The retry endpoint accelerates an already scheduled transient retry within the same three-attempt budget; terminal jobs require a new request. Zero-cost effects follow the same ledger transitions.

No arbitrary stage JSON or raw model output is retained. Reusable outputs are authorized immutable snapshot IDs, run IDs, and a strict report-shaped draft in a private staging row. Synthesis first durably reserves an invocation keyed by job and input fingerprint. A committed draft can be revalidated and finalized after restart without another model call. If the process dies after reserving/calling the model but before recording its validated draft, the outcome is ambiguous: fail with `MODEL_OUTCOME_UNKNOWN`, refund, and require review/new request. Automatic regeneration in that state is prohibited. Run 12 may add provider receipt reconciliation, preserving this invariant.

Stages expose indeterminate progress, never invented percentages. The extraction, aggregation, synthesis and validation interfaces must all be installed before intake is available. Synthetic handlers exist only in tests. This ADR does not claim calibrated evidence or model safety; those remain downstream acceptance gates. Existing advice processing is unchanged.
